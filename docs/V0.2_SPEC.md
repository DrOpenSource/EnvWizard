# EnvWizard v0.2: Technical Spec

*Status: ready to build · Branch: `v0.2` · Written 2026-10-22*

**Theme:** *meet users at the error, and make Pro real.* v0.1 waits for users to open a panel. v0.2 notices the moment `npm run dev` fails with a port jam and offers the fix right there. It also ships the four Pro features the listing already promises.

## 3. Shared foundation (Sprint 1)

### 3.1 Ownership classifier (`src/core/ProcessOwnership.ts`)
`classify(details, workspaceFolders, terminalShellPids) → 'this-terminal' | 'this-project' | 'other-project' | 'unknown'`
- **this-terminal:** a parent chain (via `parentPid`, already collected on Windows; `ps -o ppid=` on Unix) reaches the PID of one of VS Code's own terminals (`terminal.processId`).
- **this-project:** cwd (macOS/Linux) or a path in the command line (Windows) is inside a workspace folder.
- **other-project:** a cwd/path is known and lies elsewhere.
- **unknown:** nothing reliable.

F2, F3 and F8 all decide what's safe to touch based on this. Unit-test it with fixtures, and integration-test it with a server started from a VS Code terminal.

### 3.2 Polite shutdown via the owning terminal (F8)
If the holder is `this-terminal`, send Ctrl+C to that terminal (`terminal.sendText('\x03')`) and wait up to 3 s for the port to free. That is a *real* graceful stop on every OS, including the Windows case `taskkill` can't do. Only then fall back to the existing two-stage terminator.

### 3.3 Pro gating helper (`src/extension/pro.ts`)
`isProFeatureEnabled(id)` reads the license, plus the feature's own setting (every Pro automation is **opt-in**, even for Pro users). When a free user turns on a Pro setting, show **one** dismissible message with a "Learn more" link, remembered in `globalState`, and never repeated.

### 3.4 Windows reserved ports (part of F7)
Core helper that parses `netsh int ipv4 show excludedportrange protocol=tcp`. When a jam has `mayBeWindowsReserved` and nothing is listening, explain: *"Windows has reserved ports 2869–2968 for Hyper-V/WSL/Docker. Nothing to stop. Pick another port, or run `net stop winnat` & `net start winnat` as admin."*

## 4. Features

### F1 Terminal jam detector (Free) · Sprint 2
- **Listen:** `window.onDidStartTerminalShellExecution` → `new TerminalJamDetector(e.execution.commandLine.value)` → feed each chunk of `e.execution.read()`; `flush()` on `onDidEndTerminalShellExecution`.
- **Blocked jam:** scan the port, look up the holder (`ProcessDetailsCache`), classify ownership, then show a non-modal toast:
  *"🚦 Port 3000 jam: an old `node` server from **other-app** is holding it. [Free & Rerun] [Details]"*.
  - If the holder is protected, or a Docker/WSL relay, explain instead of offering a fix.
  - If nothing is listening and `mayBeWindowsReserved` is set, use the reserved-port explainer (3.4).
- **Free & Rerun:** reuse `confirmAndUnjam`, but skip the modal: clicking the toast already counts as consent. Then `terminal.shellIntegration.executeCommand(commandLine)` **only if** `commandLine.confidence !== Low`; otherwise *"Port freed. Press ↑ and Enter to run it again."*
- **Shifted (Vite/Next):** *"Your app started on 3001 instead of 3000 because 3000 is busy. Login callbacks and CORS set to 3000 may break. [Free 3000 & Restart]"*. Restart = Ctrl+C, wait for the execution to end, then rerun.
- **Limits:** at most one toast per command execution; the setting `envwizard.terminalDetection` (default on).
- **Degrades gracefully:** if the API is missing or shell integration is off (cmd.exe, some custom prompts), do nothing; the status bar radar still works. Feature-detect with `typeof vscode.window.onDidStartTerminalShellExecution === 'function'`.
- **Acceptance:** an integration test starts a blocker, runs a server in a terminal, triggers the toast action through a test-only command argument, and asserts the rerun binds the port.

### F2 Zero-click auto-unjam (Pro) · Sprint 3
- Setting `envwizard.autoUnjam` (default **off**).
- Act without asking only when **all** of these hold:
  - the holder is `this-terminal` or `this-project`;
  - it is not protected and not a database;
  - the jam came from a terminal command in this workspace.
- Otherwise fall back to the F1 toast.
- Sequence: polite stop (3.2), then terminator fallback, rerun, and a quiet status-bar message *"Freed :3000 (old copy of this project) and restarted"* with Undo-style details in the Output channel.

### F3 Project-aware Clean Slate (Free) · Sprint 3
Replace the confirm modal with a multi-select QuickPick: `this-project` and `this-terminal` servers pre-checked, `other-project` / `unknown` listed unchecked, databases and protected programs shown as disabled info rows.

### F4 Live env watcher (Pro) · Sprint 4
- On `onDidSaveTextDocument` for code files, extract keys from **that file only**, so the cost stays at O(file) and there are no workspace rescans.
- Compare against the cached audit. A new missing key shows a status-bar badge and Dev Deck highlight, plus one toast: *"Your code now uses `STRIPE_WEBHOOK_SECRET`. Add it to `.env.local`?"*
- Debounce 1 s; the setting `envwizard.envWatcher` (default **off**: opt-in like every Pro automation, see §3.3).
- Free users still see the same issue on manual Refresh, so nothing is crippled.

### F5 Encrypted `.env` snapshots (Pro) · Sprint 4
- **When:** before every EnvWizard write to an env file, and on every save of an env file.
- **How:** AES-256-GCM (`node:crypto`), with the key generated once and kept in `SecretStorage`. Files go to `globalStorageUri/snapshots/<sha256(workspace)>/<file>/<ISO time>.bin`. Keep the last 20 per file.
- **Restore:** the command *"EnvWizard: Restore .env Snapshot…"* opens a QuickPick by time, previews the diff through a **virtual document provider** (plaintext never touches disk), then restores the file, after first snapshotting the current state.
- Disclose in `PRIVACY.md`: local only, encrypted, never uploaded.

### F6 Port router (Pro) · Sprint 5 (stretch)
When the holder is `other-project` and the user wants to keep it running: *"Run this project on 3001 instead? [Yes]"*. This reruns with the port override, using the shell-specific environment-variable syntax (`$env:PORT=3001; …`, `PORT=3001 …`) or the framework flag (`--port`, `-p`), and remembers the choice per workspace (`workspaceState`). It is the riskiest feature, so it ships last and only if F1–F5 are solid.

### F7 Free extras · Sprint 5
- **`.env.example` generator:** writes keys with values stripped, and preserves comments and order.
- **Value sanity checks:** leading/trailing spaces; doubled quotes; obvious format mismatches (`OPENAI_API_KEY` not `sk-…`, `*_URL` that isn't a URL). Shown as soft hints only.
- **Multi-root:** a folder selector in the Dev Deck, and an audit per folder.
